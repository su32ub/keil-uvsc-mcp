### 已修复的本机兼容 bug
- **`UVSC_DBG_MEM_READ` 第 3 参数**：参考实现传 16（仅 AMEM 头偏移，对应新版 Tester）。本机 **2017 版 UVSC64.dll 把它当作整个可写缓冲区大小**，只传 16 必报 `status 7 "Return buffer passed too small"`。已改为传完整 `bufferSize`，报错消除。
- 残留：裸内存读对 8051 返回 `bytes_returned=0`（多地址空间 CODE/DATA/SFR 编码问题）。**主路径（符号/表达式读）不受影响**，读端口可用表达式求值替代（如 `P1`）。

### 项 4：8051 内存读修复 ✅（2026-09-11）
- **根因**：Program.cs 的 AMEM 结构体偏移**错了**——参考实现按 4×4 字节头 + data@16 组包，但 UVSOCK.h 真实布局是 `xU64 nAddr@0, UINT nBytes@8, xU64 ErrAddr@12, UINT nErr@20, aBytes@24`。DLL 从偏移 8 读 nBytes（参考实现那里是 0)→ 读 0 字节。
- 修正偏移 + nAddr 按 xU64 写入后，**8051 内存读立即可用**：读 0x00 得 `02 00 70 …`（复位向量 LJMP）、0x80/0x122 返回真实字节，`bytes_returned` 正确。
- 残留：裸数字地址的空间归属（CODE/DATA/XDATA/SFR）由驱动默认，读 0x80 得 0xC9 而符号 P0=0xFF——默认未落到 SFR 空间。空间前缀需另行确认（断点地址显示 CODE 空间前缀为高字 `0xFF00`，如 main=`0xFF0097E5`）。

### 项 6：8051 内存写 + 地址空间编码破解 ✅（2026-09-11，真机 GLink+）
- 新增 `keil_write_memory(address, bytes)`（`UVSC_DBG_MEM_WRITE(handle, AMEM, bufferSize)`，复用修正后的 AMEM 布局，数据写偏移 24）。注解 `destructiveHint=true`。
- **地址空间编码破解**：`&var` 求值直接返回带空间前缀的编码地址。实测 `&b_GeneralTime_Status` = **`0x01000130`** → **XDATA 空间前缀 = 高字 `0x0100`**；结合断点地址（CODE 前缀 = `0xFF00`），8051 UVSC 编码规律 = `0xSSSS_AAAA`（SSSS=空间，AAAA=空间内偏移）。裸数字地址默认落 CODE。
- **真机写读闭环实测**（目标 halt 下，`b_GeneralTime_Status`@XDATA）：
  - 写 `0xA5` → `read_variable`=165(0xA5)、`read_memory`=`A5`，三者一致 ✓
  - 还原写 `0x00` → `read_variable`=0 ✓（全程未 run，写完即恢复，无副作用）
- 稳妥用法：先 `keil_eval_expression &变量名` 拿编码地址，再对该地址 write/read，空间前缀自动正确。
